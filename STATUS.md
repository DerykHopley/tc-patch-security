## How to run it

The full setup, with OpenRouter, local models, live data, sign-in and web research: [docs/SETUP.md](./docs/SETUP.md). In short:

```bash
cd backend && uv sync && uv run uvicorn app.main:app --reload --port 8000   # snapshot, FakeLLM, hash embedder: no key
cd frontend && npm install && npm run dev                                    # http://localhost:5173
```

- **Snapshot mode** (the default): the frozen data as of 2026-10-13. No live calls to any source. The tests and the model check run here, so they repeat exactly.
- **Live mode:** Settings → Data → Live, then Save changes (or `DATA_MODE=live` in `backend/.env`). The real feeds are the default (`FEEDS=real`). Then **Check now** on the dashboard, `cd backend && uv run --env-file .env python -m app.refresh` on the command line, or the hourly systemd user timer (`deploy/systemd/install.sh`; [SETUP](./docs/SETUP.md#live-data-from-the-real-feeds-on-a-schedule)). `FEEDS=fake` is the made-up test data, for tests and demos only.
- With a real model: `backend/.env` (copied from `.env.example`, git-ignored) and `uv run --env-file .env ...`.
- **Defaults** (decided 2026-10-15, from the report): chat `anthropic/claude-haiku-5.5` on OpenRouter (the `OPENROUTER_MODEL` default); embedder `mxbai-embed-large` on Ollama (the Ollama default), off-topic threshold 0.58. The live app's embedder is OpenRouter's default, `google/gemini-embedding-2`, threshold 0.67 (decided 2026-10-22: best of 6 in the retrieval check; DECISIONS.md). FakeLLM and the hash embedder stay the no-setup defaults (`LLM_PROVIDER=fake`, `EMBEDDER=hash`), so tests and CI need no key and no service.
- A real embedder needs its index built once: `uv run --env-file .env python -m app.rag.build_index`. Give each embedder its own `INDEX_PATH`. In live mode, start-up embeds only what changed since the index was built (B53).
- **Web research:** `TAVILY_API_KEY` in `backend/.env` ([SETUP](./docs/SETUP.md#web-research-tavily)). **Sign-in:** `AUTH=on`, the Clerk keys and `OWNER` ([SETUP](./docs/SETUP.md#sign-in-clerk)). Both off by default.
- **Patch as an MCP server:** `cd backend && uv run python -m app.mcp_server`, started by the client ([SETUP, Try it in 5 minutes](./docs/SETUP.md#try-it-in-5-minutes)).
- Your watchlist, statuses, decision history and settings: `backend/data/state.json` (git-ignored); with sign-in on, one file per user in `backend/data/state-users/`. Settings → Start over deletes your own.
- Model-check and retrieval runs: `backend/data/evals/` (not in git); deployed (`STORE=gcs`), the bucket's `evals/` (B58, #104). The published report shows the runs named in `docs/report-src/runs.json` ([how to rebuild it](./docs/report-src/README.md)).
- The owner's own app runs on 8000/5173. Anything that changes data (the browser check, screenshots) runs on its own servers: `frontend/e2e/run.sh` picks free ports and a throwaway state file. Screenshot scripts use it too: `scripts/landing-shots.sh`, `scripts/link-preview-image.sh`.

## How to test it

No key, no network. Each command prints its own counts (passed, skipped), so this table keeps only what each check proves: a copied count goes stale with the next test, and every branch that edits it conflicts with the others (spec B retro, finding 3).

| Check | Command | What it proves |
|---|---|---|
| Backend | `cd backend && uv run pytest` | the API, the rules, the tools, the state store, the model check's scoring |
| Types, lint, unit tests | `cd frontend && npx tsc -b && npm run lint && npm test` | type check, oxlint, the frontend unit tests |
| Fixed waits | `python3 frontend/e2e/check_waits.py` | no fixed wait in the browser check without `# allowed: <reason>` |
| Browser check | `frontend/e2e/run.sh` (Firefox and Chromium) | the pages in light and dark, phone and desktop, by keyboard, with reduced motion; also the tooling tests (the fixed-wait check, the pre-commit hook, `scripts/ff-merge.sh`) |
| Slow mode | `E2E_LATENCY_MS=300 frontend/e2e/run.sh` | the same check with every API answer late: finds timing races before CI does |
| Built frontend | `E2E_BUILT=1 frontend/e2e/run.sh` | the same check against `vite build`, served by each backend as the container serves it (what CI runs) |
| Container image (B12) | `frontend/e2e/container.sh` (needs Docker) | image builds; /health, embedder check, no `.env` or secret, the Cloud Storage client present, a short browser check in Chromium |
| Report builds | `cd backend && uv run python -m app.evals fake-report --out /tmp/r.html` | FakeLLM and fake embedders; CI uploads it |

- CI ([.github/workflows/ci.yml](./.github/workflows/ci.yml)) runs all of these once per push to `main` or `spec-*`, and on pull requests from other branches. A docs-only push skips the browser check. The browser check runs as two jobs side by side, one per browser, so it takes half as long, against the built frontend (`E2E_BUILT=1`, #72): per job, Chromium 12:27 → about 8:40, Firefox 20:11 → about 16:50 (CI runs before and after; DECISIONS.md, 2026-10-16).
- **Snapshot and live in the tests:** `run.sh` starts one pair on the snapshot and a second pair in live mode on the fake feeds (two made-up days), for Check now, alerts and the run history; a refresh changes the data, so the two never share a backend. No test reaches the real feeds (a guard in `backend/tests/conftest.py` fails any that would). Web research runs against a fake Tavily (`backend/tests/fake_tavily.py`). Sign-in on is tested against faked tokens; the real-Clerk check runs only with the test instance's keys.
- The pre-commit hook (`.githooks/pre-commit`, on with `git config core.hooksPath .githooks`) runs two of CI's checks before each commit: no staged conflict markers, and the fixed-wait check.
- Merging a ticket branch into `spec-b`: `scripts/ff-merge.sh <branch>` (`--dry-run` first shows the plan). See [docs/agents/issue-tracker.md](./docs/agents/issue-tracker.md).
- Review rules that lint can't check: [CODING_STANDARDS.md](./CODING_STANDARDS.md). Each test names its check id (`A<ticket>.<n>`).
