Problem. To assess one CVE (verdict, decision record, priority, due date), each caller repeats a three-step call order, feeds review_date from one step into the next, and knows that "not_watched" is a pseudo-status.

Solution. One "watched CVEs" module, built once per request from the knowledge base, the state and the as-of date, answers assess one CVE, rows for a view and most urgent open CVE.

  • Leverage: one interface for five callers, plus B04 alerts (#37)
  • Policy read through merged settings, once
  • Tests: one assessment table, not per-tool repeats
