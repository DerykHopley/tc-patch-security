## Prototype and data

| Date | Decision | Why | Detail |
|---|---|---|---|
| 2026-10-13 | Real data frozen as a snapshot; `AS_OF` = snapshot date | Offline, repeatable tests; "new in 30 days" doesn't drift | `proto/SPEC.md` |
| 2026-10-13 | "Open CVE" = on your watchlist and not marked fixed or not affected | One clear definition for the dashboard and alerts | `proto/SPEC.md` |
| 2026-10-13 | The guard **flags** injection phrasing, doesn't block it; tool output is escaped, never stripped | Talking about attacks is normal in this domain | `proto/SPEC.md`, process map (Security) |
| 2026-10-13 | The server validates the LLM's search filters against fixed lists | A question can narrow a search, not reach outside the data | process map (Security) |
| 2026-10-13 | FakeLLM by default; local models and OpenRouter behind one `LLM` seam, switched at runtime | Tests need no key; real models plug in | STATUS.md |
| 2026-10-13 | Model check with exact checks, no LLM judge | Repeatable, cheap, honest | STATUS.md |
| 2026-10-13 | Notifications: desktop, email, ntfy; secrets only in `.env`; alert text is a fixed template without description text | A lock screen shows it; descriptions are untrusted | ALERTS-PLAN.md |
| 2026-10-14 | **LangChain, thin:** `ChatOpenAI` (`langchain-openai`) behind our `LLM` seam, for OpenRouter and local servers; tools declared with `@tool` / `bind_tools`. Own agent loop, retrieval, filter validation and RRF stay. FakeLLM stays our own class above the seam | Meets the brief's core line ("LangChain with OpenRouter") with one dependency at one seam; keeps every step explainable. `SelfQueryRetriever` would pass the LLM's filters to the store unchecked | docs/adr/0001-thin-langchain.md |
| 2026-10-14 | **Vector store: Chroma, in-process** (`PersistentClient`, no server; user's pick over numpy, sqlite-vec, LanceDB). The index is built by a script and loaded at start, and records which embedding model built it (a mismatch is an error) | Recognisable vector database; the earlier pain was Chroma's JS client needing a server | SOURCE-CHECKS.md (Chroma) |
| 2026-10-14 | **Hybrid search is ours:** in-process BM25 (`rank_bm25`) over the same chunks, merged with Chroma's results by our RRF. The server turns validated filters into Chroma `where` clauses (`$and` of single conditions; dates as ints like `20260914`, severity as a rank); BM25 applies the same filters in Python | Local Chroma has no BM25 or hybrid search (Cloud only); range filters compare numbers only | SOURCE-CHECKS.md (Chroma) |
| 2026-10-14 | **Embeddings: OpenRouter `openai/text-embedding-3-small`** via LangChain `OpenAIEmbeddings` (`check_embedding_ctx_length=False`). A **local embedder through Ollama** is compared in the model check (to download; which model is for the spec). The hash embedder stays as the test fake | Same vectors everywhere, about a cent for the whole index, same key as the chat | SOURCE-CHECKS.md (Embeddings) |
| 2026-10-14 | **BM25 is our own**, about 60 lines in `backend/app/rag/keyword.py`, not `rank_bm25` or `bm25s`. Our tokeniser keeps CVE, CWE and ATLAS ids whole (`cve-2024-8309`, `aml.t0051.001`) | `rank_bm25` has had no release since 2022 and can't filter; `bm25s` adds scipy. Our own code applies the same filters as Chroma and scores 1,680 chunks in a few ms | #12 |
| 2026-10-14 | **A source's score is the fused RRF score**, not cosine similarity | BM25 and cosine scores aren't on the same scale, so only the fused rank means the same for every source | #12 |
| 2026-10-14 | **Open: off-topic refusal and BM25.** BM25 has no score threshold, so a keyword hit can bring sources for an off-topic question. The refusal threshold, tuned with the real embedder in A20, must account for keyword hits too | R6 (no sources for off-topic questions) depends on it | #12, #22 |
| 2026-10-14 | **Dev panel choices (A11) are their own part of the state**, saved by `PUT /dev/settings`, not inside `/settings`. They apply on the next call (an LLM router reads them per call). With `DEV_PANEL` off, every `/dev` route is a 404 and the env defaults apply, even if choices were saved. Model discovery uses the same local-URL guard as the model and never follows a redirect | The Settings page and the Dev page save separately (two save bars); a deployment with the dev panel off can't be steered by a saved local URL; a local server can't bounce the request elsewhere | #13 |
| 2026-10-14 | **Model check and retrieval check (A12):** model-check questions are the FakeLLM scripts with an `expect`; a new kind of check is one function in `app/evals/checks.py`. The model is fixed when a run starts. Retrieval: 39 questions from structured fields (one CVE per product, one CWE per OWASP category, each LLM risk by name, each LLM risk → its ATLAS techniques), ranked by document, scored for vector alone and for hybrid, MRR to rank 10, the off-topic threshold ignored. Runs are JSON next to the state file (`backend/data/evals/`, not in git); the report inlines `tokens.css` and loads nothing | Exact and repeatable; vector alone is what compares embedders, hybrid is what the chat gets; the threshold is tuned separately in A20 | #14 |
| 2026-10-14 | **Explain levels (A19):** `explain_level` (`simple`, `normal`, `deep_dive`) is a single value in `/settings`; a chat request may override it for that message only, and the reply says which level was used. The chat header's switch is for the next question only and never saves. "Explain it" and "Ask about this" always use the saved level. In the model check, Q12 is asked once per level: every answer must pass its checks, cite the same sources, and Flesch reading ease must fall from simple to deep dive | The level changes wording only, so the check compares answers to each other; no LLM judge | #21 |
| 2026-10-14 | **Flesch reading ease is our own**, about 20 lines in `backend/app/evals/readability.py`, not `textstat`. Syllables by vowel groups (silent final "e" dropped, "-le" kept), *unverified* against a dictionary count | The formula is one line; `textstat` adds `pyphen` and a dictionary for the syllable count only. Comparing three answers from the same model needs a count that is the same every run, not an exact one | #21 |
