Deep dive
**Prompt Injection – What It Is** Prompt injection is an attack technique where an adversary supplies specially-crafted input (the *prompt*) to a large language model (LLM) that causes the model to deviate from its intended behavior. The goal is to: * **Bypass safety or policy guardrails** (e.g., “You are a helpful assistant” → “Ignore all previous instructions…”). * **Extract the system prompt or internal parameters** (meta-prompt extraction). * **Force the model to generate disallowed content** (jailbreak injection). * **Manipulate downstream logic** by feeding the model with instructions that alter the application’s flow. The attack works because LLMs are trained to follow the *first* coherent instruction they encounter in the input sequence. If an attacker can place a higher-priority instruction earlier than the legitimate system prompt, the model will obey the attacker’s instruction instead. **Key MITRE ATLAS Techniques** | Technique ID | Name | Description | |--------------|------|-------------| | **AML.T0051.000** | LLM Prompt Injection – Direct (Meta Prompt Extraction) | The adversary injects a prompt that extracts the system prompt or model parameters. | | **AML.T0051.001** | LLM Prompt Injection – Indirect | The adversary crafts input that indirectly triggers a prompt-injection scenario (e.g., via user-controlled fields). | | **AML.T0054** | LLM Jailbreak Injection – Direct | The adversary injects a prompt that overrides safety constraints, causing the model to produce prohibited outputs. | **Prevention Strategies (OWASP LLM01:2025)** 1. **Constrain Model Behavior with External Guardrails** * **Validate & sanitize** all user-supplied text before it reaches the LLM. * **Enforce policy rules** (content filters, rate limits, allowed topics) in a separate service that decides whether the request should be forwarded to the model. * **Use a “system prompt” only for immutable policy** and never expose it to user-controlled input. 2. **Implement Robust Input Validation & Whitelisting** * **Whitelist** expected prompt structures (e.g., a fixed prefix such as “You are a …” that cannot be altered). * **Reject** any input that attempts to prepend or replace the system prompt (detect patterns like “Ignore previous instructions”, “You are …”, “System: …”). * **Limit token length** and enforce a maximum depth of nested instructions. 3. **Separate Concerns – Offload Safety Checks** * Perform **content moderation** and **policy enforcement** outside the LLM (e.g., using a rule-based classifier or a secondary LLM with a hardened system prompt). * Only forward requests that pass these checks to the primary generative model. 4. **Use “Safe Prompt Templates”** * **Template-based prompting**: embed the system prompt in a fixed template that cannot be overridden by user input. * Example: ```text SYSTEM_PROMPT = "You are a helpful, honest assistant that follows these rules: ..." USER_INPUT = "<user-provided text>" FINAL_PROMPT = SYSTEM_PROMPT + "\n\nUser: " + USER_INPUT ``` * Ensure the template is **immutable** at runtime. 5. **Detect and Block Injection Attempts** * **Pattern detection**: scan for known injection keywords (`ignore`, `override`, `system:`, `!`, etc.). * **Heuristic scoring**: assign a risk score based on the presence of suspicious tokens; block or flag high-score inputs. * **Rate-limit** repeated attempts that contain injection patterns. 6. **Regularly Update and Patch the LLM Deployment** * Monitor **MITRE ATLAS** and **CVE** databases for new prompt-injection vectors. * Apply vendor patches or configuration changes that harden the model’s prompt handling (e.g., newer Ollama or LangChain releases that include stricter prompt-precedence logic). 7. **Logging & Auditing** * Log every request that reaches the LLM, including the exact prompt sent. * Review logs for anomalies (e.g., unexpected system-prompt overrides) and trigger alerts for potential injection attempts. **Technical Details** * **CWE Mapping** – Prompt injection often maps to **CWE-918: Server-Side Request Forgery** when the attacker manipulates request parameters, and to **CWE-400: Uncontrolled Resource Consumption** when the model is forced to generate excessive output. * **CVSS Vector** – For a typical prompt-injection vulnerability in an LLM API, a plausible CVSS v3.1 vector might be: ``` AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H ``` (Attack Vector: Network, Attack Complexity: Low, Privileges Required: None, User Interaction: None, Scope: Unchanged, Confidentiality: High, Integrity: High, Availability: High). * **ATLAS Technique ID** – The primary technique is **AML.T0051.000** (Direct Prompt Injection). Preventing it requires **external guardrails**, **strict input validation**, **immutable system prompts**, **pattern detection**, and **continuous monitoring** of security advisories. By separating safety logic from the generative model and hardening the prompt pipeline, you can significantly reduce the risk of successful prompt-injection attacks.
